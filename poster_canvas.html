ชื่อส่วนงาน : ภาควิชาวิศวกรรมคอมพิวเตอร์ คณะวิศวกรรมศาสตร์ กำแพงแสน
ชื่อผลงาน : CPE Assets warehouse: ศูนย์กลางข้อมูลร่วมครุภัณฑ์ของ คณะวิศวกรรมศาสตร์ กำแพงแสน
VP การเสนอคุณค่า :
  • ศูนย์กลางข้อมูลร่วม (Single Source of Truth): บูรณาการทะเบียนครุภัณฑ์ การเบิกยืม-คืน และงานแจ้งซ่อมข้ามระบบ (API & Excel) เป็นฐานเดียวกัน
  • ทำความสะอาดข้อมูลอัตโนมัติ 100%: แปลงข้อความสถานที่อิสระ (รหัสห้อง/อาคาร) ให้มีมาตรฐานแม่นยำ พร้อมบันทึก Cleaning Log โปร่งใส
  • เรดาร์ตรวจจับความเสี่ยง Real-time: ตรวจจับพฤติกรรมผิดปกติ เช่น การผูกขาดเครื่อง (>3 ครั้ง ใน 7 วัน) และการส่งคืนล่าช้าเชิงรุก
  • เพิ่มประสิทธิภาพและลดภาระงาน: ลดเวลาจัดเตรียมและประมวลผลรายงานสรุปจาก 2-3 สัปดาห์ เหลือเพียงระดับวินาที
C/S กลุ่มเป้าหมาย :
  • ผู้บริหารคณะและหัวหน้าภาควิชา: ต้องการข้อมูลเชิงประจักษ์ประกอบการวางแผนงบประมาณซ่อมบำรุงและจัดซื้อทดแทน
  • เจ้าหน้าที่งานพัสดุและอาคารสถานที่: ใช้ติดตาม ตรวจสอบ และออกรายงานสถิติสินทรัพย์ประจำปี
  • อาจารย์และผู้ดูแลห้องปฏิบัติการ: ตรวจสอบความพร้อมใช้งานของอุปกรณ์การเรียนการสอน
  • นิสิตและบุคลากร: ได้รับการจัดสรรและเข้าถึงครุภัณฑ์อย่างทั่วถึงและเป็นธรรม
KK ความรู้หลักที่ต้องใช้เพื่อความสำเร็จ :
  • สถาปัตยกรรมคลังข้อมูล (Star Schema, Dimensions & Facts)
  • การทำความสะอาดข้อความภาษาไทย (Rule-based & Regex)
  • วงจรชีวิตและการบริหารพัสดุในมหาวิทยาลัย
  • การออกแบบแดชบอร์ดเชิงบริหาร (UI/UX Design)
SoK แหล่งที่มาของความรู้หลัก :
  • คณาจารย์ภาควิชาวิศวกรรมคอมพิวเตอร์
  • เจ้าหน้าที่งานพัสดุและงานอาคารสถานที่
  • ฐานข้อมูลระบบ CPEAssets และ Google Form เดิม
  • มาตรฐานคลังข้อมูลสากลและคู่มือ KM มก.
KR ทรัพยากรหลัก :
  • ทีมนิสิตและอาจารย์ที่ปรึกษาโครงการ
  • ชุดข้อมูลประวัติการแจ้งซ่อมและเบิกยืม
  • Cloud Server (AWS EC2), Docker, MySQL 8, PHP
KA กิจกรรมหลัก :
  • (1) สำรวจและรวบรวมปัญหาความต้องการจากผู้มีส่วนได้ส่วนเสีย
  • (2) สกัดกฎการแปลงข้อมูลสถานที่ (Location Rules) และประเภทงานซ่อม
  • (3) พัฒนาและทดสอบท่อส่งข้อมูล ETL อัตโนมัติ (etl_warehouse.py)
  • (4) สร้าง Data Warehouse (Star Schema) และ Web Analytics Hub 4 โมดูล
  • (5) ติดตั้งระบบบน Cloud Server (AWS EC2) และทดสอบประเมินซ้ำ
  • (6) ถอดบทเรียน จัดทำคู่มือ SOP และถ่ายทอดองค์ความรู้
Kme ตัววัดความสำเร็จที่สำคัญ :
  • ความถูกต้องของข้อมูลสถานที่หลังผ่าน ETL = 100%
  • เวลาที่ใช้สรุปรายงานลดลง >90% (เหลือระดับวินาที)
  • ความพร้อมใช้งานของระบบ (System Uptime) ≥ 99%
  • ความพึงพอใจของผู้ใช้งานระบบระดับดีมาก ≥ 85%
Ut ประโยชน์ที่ได้รับ :
  • มีศูนย์กลางข้อมูลร่วมที่ถูกต้อง แม่นยำ และเรียกดูได้ตลอด 24 ชม.
  • ผู้บริหารเห็นภาพรวมสินทรัพย์ การชำรุด และจุดเสี่ยงเชิงพื้นที่ชัดเจน
  • เจ้าหน้าที่ลดภาระงานซ้ำซ้อนและลดความเสี่ยงข้อมูลสูญหาย
  • กระจายทรัพยากรการศึกษาอย่างเป็นธรรม ขจัดการผูกขาดเครื่อง
As สินทรัพย์ความรู้ :
  • ฐานข้อมูลคลังข้อมูลกลาง Star Schema (8 Dimensions, 4 Facts)
  • ชุดอัลกอริทึมและ Regex Rules ทำความสะอาดข้อมูลสถานที่ของคณะฯ
  • พจนานุกรมข้อมูล (Data Dictionary) และคู่มือสถาปัตยกรรมระบบ
  • ตรรกะตรวจจับความเสี่ยงการเบิกยืม (Risk Radar & Monopoly Logic)
KP คู่ความร่วมมือหลัก :
  • ภาควิชาวิศวกรรมคอมพิวเตอร์ และ งานพัสดุและทรัพย์สิน คณะฯ
  • งานอาคารสถานที่และยานพาหนะ และ งานบริการเทคโนโลยีสารสนเทศ
M การบำรุงรักษาสินทรัพย์ความรู้ :
  • ปรับปรุงกฎทำความสะอาดสถานที่ (Location Rules) เมื่อมีการเพิ่ม/เปลี่ยนชื่อห้อง
  • สำรองข้อมูลคลังข้อมูลและสแนปช็อตครุภัณฑ์ตามรอบสัปดาห์/เดือน
  • ทบทวนเกณฑ์เรดาร์ความเสี่ยงร่วมกับเจ้าหน้าที่พัสดุปีละ 1 ครั้ง
LC วงจรการเรียนรู้ :
  • รวบรวมฟีดแบ็กและปัญหาจากการใช้งานจริงในแต่ละรอบวงจร
  • วิเคราะห์ข้อจำกัดของข้อมูลและคำค้นหาใหม่ๆ ผ่านการประชุม AAR
  • ปรับปรุงสถาปัตยกรรมและกระบวนการทำงานให้มีประสิทธิภาพยิ่งขึ้น
Pt แหล่งจัดเก็บและเผยแพร่สินทรัพย์ความรู้ :
  • เว็บพอร์ทัลกลาง CPE Assets Warehouse บน Cloud Server (AWS EC2)
  • คลังซอร์สโค้ดกลาง GitHub Repository พร้อมระบบ Version Control
  • เอกสารคู่มือมาตรฐาน (SOP) และ Data Dictionary บน Google Drive ภาควิชาฯ

ตรวจจับการผูกขาดเครื่อง

📌 1. ที่มาและความสำคัญของปัญหา (Background & Pain Points)

คณะวิศวกรรมศาสตร์ กำแพงแสน มีครุภัณฑ์มูลค่าสูงกระจายตัวอยู่ตามภาควิชาและส่วนกลางเป็นจำนวนมาก การดำเนินงานเดิมประสบปัญหา ความกระจัดกระจายของข้อมูล (Data Silos) ระหว่างระบบ API ของครุภัณฑ์ และ Google Form แจ้งซ่อมอาคารสถานที่ ข้อมูลสถานที่บันทึกเป็นข้อความอิสระไม่เป็นมาตรฐาน ขาดระบบเรดาร์เตือนภัยความเสี่ยง และต้องใช้เวลาหลายสัปดาห์ในการรวบรวมรายงานเชิงบริหารด้วยมือ

⚙️ 2. สถาปัตยกรรมคลังข้อมูลและ ETL (Architecture & ETL Engine)

Automated ETL & Cleansing Pipeline :
  • ดึงข้อมูลจาก REST API (CPEAssets) และ Google Form (Excel)
  • ระบบ Rule-based Text Processing แปลงข้อความสถานที่ (เช่น 'E9203' ➔ อาคาร 9 ชั้น 2 ห้อง 03)
  • คัดกรองข้อมูลทดสอบ และตัดข้อมูลส่งซ้ำ บันทึก Log โปร่งใส
Star Schema Data Warehouse (MySQL 8) :
  • 8 Dimensions : Date, Dept, User, Maint Type, Category, Type, Location, Asset
  • 4 Fact Tables : Periodic Inventory Snapshot, Borrow Transactions, Asset Maintenance, General Repair
💡 Key Innovation: ระบบสามารถถ่ายโอนและจัดโครงสร้างข้อมูลแบบอัตโนมัติ ทำให้เกิดฐานข้อมูลกลาง (Single Source of Truth) ที่พร้อมใช้วิเคราะห์ข้ามมิติได้ทันที

📊 3. ศูนย์กลางข้อมูลและการแสดงผลอัจฉริยะ (CPE Assets Analytics Hub)

4 โมดูลแดชบอร์ดหลัก :
  1. ทะเบียนและสถานะครุภัณฑ์: มูลค่าการครอบครองและอัตราเสื่อมสภาพ
  2. การเบิกยืม-คืนและเรดาร์ความเสี่ยง: วิเคราะห์พฤติกรรมการใช้งาน
  3. งานซ่อมบำรุงและจุดเสี่ยงเชิงพื้นที่: สถิติความเสียหายตามอาคาร/ชั้น
  4. รายงานสรุปภาพรวมเชิงบริหาร: สถิติประจำปีสนับสนุนการวางแผนงบ
Risk & Anomaly Radar (ตรวจจับความเสี่ยง) :
  • ผูกขาดเครื่องต่อเนื่อง: ยืมชิ้นเดิมติดต่อกัน > 3 ครั้ง (ห่างกัน ≤ 7 วัน) ตรวจพบ 2 รูปแบบ
  • รายการส่งคืนล่าช้า (Overdue): ติดตามผู้ยืมเกินกำหนดเวลา
  • ชำรุดตอนคืนและเปลี่ยนเครื่องทดแทน: เฝ้าระวังอุปกรณ์เสียหายสูง

🏆 4. ผลสัมฤทธิ์และผลกระทบเชิงประจักษ์ (Outcomes & Impact)

✅ ด้านธรรมาภิบาล (Good Governance): ทรัพย์สินของมหาวิทยาลัยได้รับการตรวจสอบ ติดตาม และกระจายการใช้งานอย่างเป็นธรรม ลดปัญหาการผูกขาดเครื่อง
✅ ด้านความคุ้มค่างบประมาณ (Value for Money): ผู้บริหารมีข้อมูลเชิงประจักษ์สนับสนุนการวางแผนซ่อมบำรุงเชิงป้องกัน (Preventive Maintenance) และจัดซื้อทดแทนได้อย่างคุ้มค่า
✅ ความยั่งยืนขององค์ความรู้ (Knowledge Sustainability): จัดทำคู่มือ SOP, Data Dictionary และสคริปต์อัตโนมัติ ทำให้องค์ความรู้ไม่ขึ้นกับตัวบุคคล และสืบทอดได้อย่างต่อเนื่อง
